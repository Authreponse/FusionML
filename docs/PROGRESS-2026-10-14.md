## 二、本轮修好的（全部已验证）

### 1. 属性丢弃的计数 bug（ASM 崩）

**症状**：`java.lang.IllegalArgumentException at ClassReader.readTypeAnnotationTarget`
→ `GameTransformer.readClassNode` → `BrandingPatch.process`（Fabric 启动早期）。

**根因**：丢弃属性时把长度写成 0，**但属性计数没减**。ASM 去读
`RuntimeVisibleTypeAnnotations` 的 `num_annotations` 就越界。
JVM 的 `defineClass` 却能过 —— 典型的"JVM 认、ASM 不认"。

**修法**：`ConstantPoolTransplant.remapToNew` 改为**先建属性区、最后写计数**；
`new byte[0]` 表示"丢弃"，不写也不计数。

**新增防线**：`PatchedBase.asmParseCheck` —— 自检里**借 ASM 再读一遍**产物。
这补上了我们自己的解析器（按长度跳过属性）看不见的那一类结构错误。

### 2. 超类判据修对了（关键）

**症状**：`MappedRegistry` 被误判成"对方没按新超类用它" → 保留原版 →
`VerifyError: 'MappedRegistry' is not assignable to 'BaseMappedRegistry'`。

**走过两个弯路（都记在代码注释里）**：

- "谁调用本类上的新超类方法" —— 字节码里 owner 写的是**父类**
  （`BaseMappedRegistry.setMaxId`），按本类名永远找不到；
- "本类 `<init>` 是否调新超类构造器" —— **两边都有**（语法强制），不构成差异。

**最终判据**：**这个类自己的方法体里，有没有调用"只存在于新超类"的方法**。

**实测验证**（`WhyReplaced`）：

```
Level         → false（保留原版 → c2me 能注入）      ✅
MappedRegistry → true （整类换 → 不会 VerifyError）  ✅
```

顺带修了 `vanillaSuperOf` 返回 `java/lang/Object` 时读不到类、
导致"原版祖先方法"集合为空的问题。

**最后一项为什么必须做**：`ldc` 是单字节索引（上限 255），而原版 `Level` 的常量池

升格会移动后续所有指令偏移，必须同步修：跳转偏移、异常表、`StackMapTable` 帧偏移。
**这是"小型汇编器 + 偏移重算"**，代码里已留了 `promotions` 参数与 `fixAfterPromotion` 的位置。

